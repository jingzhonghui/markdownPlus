## 1. 技术选型

| 层面 | 选型 | 理由 |
|------|------|------|
| 桌面框架 | **Electron 33+** | 生态成熟、跨平台一致性好、Node.js 后端处理文件 I/O 方便 |
| 前端框架 | **Vue 3 + TypeScript** | 组件化开发，生态成熟，与 WYSIWYG 编辑器集成方便 |
| 编辑器内核 | **CodeMirror 6**（源码）+ **ProseMirror**（IR 模式） | CM6 适合源码编辑，ProseMirror 负责即时渲染 |
| Markdown 解析 | **markdown-it** | 可扩展、支持 CommonMark + GFM，插件生态丰富 |
| 代码高亮 | **Shiki** | 支持 VS Code 主题，渲染准确 |
| 样式方案 | **Tailwind CSS** | 原型已使用，保持一致 |
| 构建工具 | **electron-vite** | Electron 专用 Vite 构建，主进程/预加载/渲染进程分离，开发体验好 |
| 文件格式 | **ZIP (adm-zip + archiver)** | adm-zip 读取解压，archiver 写入压缩 |
| 图片压缩 | **sharp** | 高性能图片处理，支持多种格式 |
| 分屏面板 | **splitpanes** | Vue 3 兼容的可拖拽分屏组件 |
| 窗口方案 | **frameless + 自定义标题栏** | 移除系统边框，自定义窗口控制按钮 |

## 5. 风险与应对

| 风险 | 影响 | 概率 | 应对策略 |
|------|------|------|----------|
| ProseMirror ↔ Markdown 转换精度不足 | 高 | 中 | 使用 prosemirror-markdown + 自定义 serializer，逐步扩展覆盖 |
| Electron 包体积较大 | 中 | 高 | 使用 electron-builder 精简，懒加载非核心模块 |
| 大文件（>10MB）编辑卡顿 | 高 | 中 | 虚拟滚动 + 增量解析，性能测试前置 |
| Electron 跨平台渲染差异 | 中 | 低 | 统一 Chromium 版本，CSS 前缀处理 |
| 图片压缩质量/速度平衡 | 中 | 低 | 提供可配置压缩参数，默认使用 WebP |
| 跨平台打包/签名问题 | 中 | 中 | 提前搭建 CI（GitHub Actions），每个平台单独测试 |
